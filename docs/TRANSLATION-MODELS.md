## Native Marian alternative after preflight

The [source preflight report](reports/MODEL-PREFLIGHT-2026-10-29.md) and [separate manifest](experiments/marian-source-preflight.json) record original Marian NPZ releases totaling 1,150,647,069 archive bytes. The installed converter/dependencies can inspect their vocabulary and distinct source/target SentencePiece models without PyTorch or Transformers. The initial preflight fetched only small metadata ranges; the later verification below completed archive identities and NPZ structural checks. Full converter compatibility, conversion resources and quality remain unverified. This is a larger download than the selected Hugging Face weights in the table, with fewer additional dependencies.

Both native archives carry **CC-BY-4.0** LICENSE files, including EN → TR, whose Hugging Face card above labels its separately packaged weights Apache-2.0. Keep these source identities and licensing observations separate. Metadata shows differing token ID spaces and some tokenizer pieces missing from the Marian vocabulary; special tokens, unknown handling and normalization require explicit tests. Current available RAM failed conservative 2 GiB / 4 GiB guards; disk passed a 5 GiB temporary budget plus 10 GiB reserve. These guards are not measured conversion peaks. No download/conversion or runtime activation is enabled by the manifest or offline preflight tool.

After scoped approval, both original archives were downloaded and [verified in full](reports/MODEL-SOURCES-2026-10-29.md). A [separate source-verification lock](experiments/marian-verified-sources.json) now pins observed archive and extracted-file SHA-256 values. The offline NPZ inspector verified headers, bounded safe YAML and every nested ZIP CRC without loading tensor arrays. Both configurations pass initial option checks; full converter compatibility is untested. Available RAM remains below the guards, so no conversion was attempted. This is source preparation, not a translation-quality improvement or runtime installation.

## Integration boundary

The proposed evaluation uses an isolated conversion environment. PyTorch and Transformers are currently absent from the project environment; they will not be added to the running application environment. CPU/int8 CTranslate2 conversion is a candidate approach: the [official converter documentation](https://opennmt.net/CTranslate2/guides/transformers.html) lists MarianMT and M2M100 and explains required special-token handling. Conversion must explicitly test source/target tokenizer differences, EOS/start tokens, unknowns and normalization; the existing single-SentencePiece adapter cannot simply be reused.

An experiment must finish dependency/file pinning, verify free disk space with a declared temporary footprint, preserve existing models and use offline inference after installation. Prefer safetensors where provided; any legacy PyTorch weight must use an explicit weights-only loader and no remote model code. Runtime limits, consent, budget rules and cancellation remain in force. No automatic cloud fallback, provider bill or 24/7 service is introduced.

Only after approval for the additional local download/conversion work should the candidate be installed in a separate directory. Screen development texts first. If it passes without new critical regressions, freeze the adapter, rerun the original WAV set and review changed exact outputs, then run the reserved subset and timing/safety/package gates. No default activation, model release upload or new runtime version follows merely from installation. Human listening and owner-run Discord acceptance remain separate.
